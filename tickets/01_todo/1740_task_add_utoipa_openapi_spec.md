# Task: Annotate handlers with `utoipa-axum`; emit OpenAPI spec at build time

Parent: `1700_story_backend_framework_migration.md`
Depends on: `1710_task_port_admin_api_to_axum_router.md`

## Background

After 1710, every admin endpoint is a typed Axum handler. The
request/response shapes are already serde-derived in
`crates/shared-protocol/src/` and `crates/backend-backendd/src/`.
There is no OpenAPI surface today; ts-rs emits TypeScript types
for the FE but no operation contract (paths, methods, status
codes, parameter shapes).

This ticket adds [`utoipa`](https://docs.rs/utoipa) and
[`utoipa-axum`](https://docs.rs/utoipa-axum) annotations so the
backend itself is the source of truth for the API contract.

## Scope

- Add dependencies to `crates/backend-backendd/Cargo.toml`:
  - `utoipa`
  - `utoipa-axum`
- Add `#[derive(utoipa::ToSchema)]` to every request/response DTO
  the admin API exposes. DTOs live in:
  - `crates/shared-protocol/src/entities.rs`
  - `crates/shared-protocol/src/policy.rs`
  - `crates/shared-protocol/src/service.rs`
  - `crates/backend-backendd/src/admin_api/*` (admin-only request
    shapes inside each subdomain module)
  - `crates/backend-backendd/src/operators.rs` (Principal,
    Operator-related response shapes)
  - `crates/backend-backendd/src/http/responses.rs`
    (ServiceErrorResponse → schema for the standard error body)
  - Any other crate exposing types that cross the admin API
    boundary.
  - Where ts-rs annotations exist today (`#[ts(export)]`), keep
    them. utoipa schemas are orthogonal; the dual annotation is
    temporary and goes away in 1750.
- Annotate every admin handler with `#[utoipa::path(...)]`:
  - Method, path, request body schema, response schemas for each
    status code (200, 400, 401, 403, 404, 409, 503, etc., as
    used by that handler), tags grouping handlers by subdomain
    (`users`, `stores`, `client_instances`, `secrets`,
    `resources`, `pairs`, `policy`, `auth`, `bootstrap`,
    `overview`).
  - Authentication / CSRF requirements as a `security` annotation:
    a `session_cookie` SecurityScheme plus a `csrf_header`
    SecurityScheme for state-changing endpoints. Public auth +
    bootstrap routes are marked as not requiring either.
- Register the router with `utoipa-axum::router::OpenApiRouter`
  (or the equivalent at the chosen version) so the spec is
  generated from the same handler registrations Axum uses. No
  duplicated path lists.
- Emit the spec at build time:
  - Add an integration test (e.g.
    `crates/backend-backendd/tests/openapi_export.rs`) that
    serializes the generated `OpenApi` to JSON and writes it to
    a known repo path (decide: `crates/backend-backendd/openapi.json`
    is the conventional location; document the choice in the PR).
  - The test is run by `cargo test --workspace` and fails if the
    written spec drifts from the committed file (analogous to
    the existing `ts_export` test pattern).
  - Add a `Justfile` / `xtask` command or document the manual
    flow for refreshing the spec after handler changes.
- mTLS runtime API is **not** included in the spec. The runtime
  endpoints are not consumed by the SPA; they are an internal
  daemon-to-backend contract. Document in `docs/backend.md` that
  the OpenAPI spec covers `/v1/admin/*` only.
- Document, in a short section of `docs/backend.md`, what the
  spec is, where it lives, and how to regenerate it. Add a
  callout that the spec is the source of truth for the FE
  client generated in 1750.

## Out of scope

- Frontend client generation (lands in 1750).
- Removing ts-rs from the backend (still emits while FE runs on
  ts-rs in this step; removed in 1750).
- Documenting the mTLS runtime API. The runtime contract is
  defined in `crates/shared-protocol/src/service.rs` and stays
  there.
- Hosting a Swagger / Redoc UI from the daemon. Out for now; the
  spec is a build artefact, not a runtime feature.

## Acceptance criteria

- [ ] `utoipa` and `utoipa_axum` are imported in
      `crates/backend-backendd/src/`.
- [ ] Every admin handler (every `(method, path)` pair under
      `/v1/admin/*`) carries a `#[utoipa::path(...)]` annotation.
- [ ] Every DTO that appears in an admin request or response body
      derives `utoipa::ToSchema`.
- [ ] `crates/backend-backendd/openapi.json` (or the agreed
      location) exists in the repo and is regenerated by
      `cargo test --workspace`.
- [ ] A test fails when the generated spec drifts from the
      committed file.
- [ ] The spec covers every endpoint reachable under `/v1/admin/*`
      and excludes `/v1/wrappers*` / `/v1/wrapper-invocations*`.
- [ ] Spec round-trips through a third-party validator (e.g.
      `openapi-cli validate` or a Rust validator crate) without
      errors. Either run this in CI or document the manual check.
- [ ] `docs/backend.md` documents the OpenAPI spec location and
      regeneration command, and states that runtime endpoints are
      not in the spec.
- [ ] `cargo test --workspace` passes.
- [ ] `cargo fmt -- --check` and
      `cargo clippy --all-targets --workspace -- -D warnings` pass.
- [ ] `cd web && npm test` and `cd web && npm run build` pass
      without source changes in `web/`.
- [ ] `nix build .#checks.x86_64-linux.vm-test` passes.
