# Task: Replace ts-rs FE types and hand-rolled `apiFetch` with an `openapi-fetch` generated client

Parent: `1700_story_backend_framework_migration.md`
Depends on: `1740_task_add_utoipa_openapi_spec.md`

## Background

After 1740, the backend emits an OpenAPI spec that fully describes
`/v1/admin/*`. The current FE talks to the backend through:

- `web/src/api/types/` — ~100 TypeScript files generated by ts-rs
  at Rust build time and committed.
- `web/src/api/client.ts` — ~340 lines: hand-rolled `apiFetch` /
  `apiJson<T>` helpers, manual CSRF cookie read + `X-CSRF-Token`
  injection, manual `credentials: "include"`, manual `ApiError`
  class, and a centralised error-code switch in
  `web/src/lib/error-message.ts`.

We replace this with `openapi-fetch`, a thin typed client driven
by the OpenAPI spec. Existing TanStack Query usage stays; only
the lowest layer changes.

## Scope

- Add dev dependencies to `web/package.json`:
  - `openapi-typescript` (to generate types from the spec) — or
    the equivalent CLI that ships with `openapi-fetch`.
  - `openapi-fetch` (the runtime client).
- Add a `web/scripts/generate-api.{ts,sh}` that reads the spec
  emitted by 1740 (`crates/backend-backendd/openapi.json` or the
  agreed location) and writes a single TypeScript types file
  (e.g. `web/src/api/schema.ts`).
- Wire the generation into the build:
  - A `web/package.json` script (`"generate:api"`).
  - The `prebuild` / `pretest` hook runs it, so a stale spec
    breaks the FE build.
  - The Nix build of `backend-backendd` produces the spec at the
    right path before `web/`'s `npm run build` runs; verify the
    flake's `web` derivation depends on the backend spec
    artefact.
- Replace `web/src/api/client.ts` with a thin wrapper around
  `createClient<paths>` from `openapi-fetch`:
  - `client.use({...})` middleware that reads the `__Host-uw-csrf`
    cookie via `document.cookie` and sets `X-CSRF-Token` on
    non-GET/HEAD/OPTIONS requests. This single middleware
    replaces the manual CSRF logic.
  - `credentials: "include"` set as the default request init.
  - An `ApiError` class is still useful for consumers; it now
    wraps the typed error responses from the generated client.
    Map non-2xx responses into `ApiError { status, code, message }`
    once, in one place. Preserve the existing `code` field so
    `web/src/lib/error-message.ts`'s switch keeps working.
  - Helpers like `apiJson<T>` go away. Call sites use
    `client.GET("/v1/admin/users", {...})`,
    `client.POST("/v1/admin/users", { body })`, etc. — fully
    typed against the spec.
- Delete `web/src/api/types/` entirely. Any consumer that
  imported `import type { Foo } from "@/api/types"` either:
  - reads types off the generated schema directly
    (`paths["/v1/admin/foo"]["get"]["responses"]["200"]["content"]["application/json"]`),
    or — preferably — picks them up automatically through
    `openapi-fetch`'s inference,
  - or references a small `web/src/api/types.ts` that re-exports
    *named* schema types via the `openapi-fetch` `components`
    API, for cases where a callsite needs a standalone type name.
- Update every callsite that today calls `apiFetch` / `apiJson`
  to use the new client. Suggested order while editing:
  - Start with `web/src/router.tsx` (whoami + bootstrap flow,
    the auth root guard).
  - Then per-page files under `web/src/pages/` and their
    `dialogs/` siblings.
  - Then any hook or component that consumes generated types.
- Remove ts-rs from the backend if every admin DTO now has
  `utoipa::ToSchema`. Specifically:
  - Delete `#[ts(export)]` from every type.
  - Remove `ts-rs` from `Cargo.toml` of every crate that uses
    it.
  - Remove the `ts_export` integration test (its replacement is
    the OpenAPI export test from 1740).
- Update `docs/backend.md` and any developer documentation to
  point at the new generation flow: backend emits OpenAPI →
  `npm run generate:api` produces `schema.ts` → app code uses
  `client.{GET,POST,...}` with full inference.
- Update Playwright tests (`web/tests` or wherever they live) if
  they assert on response shapes via the deleted types. They
  should still pass against the generated schema; expect minor
  import-path changes only.

## Out of scope

- Adopting `@hey-api/openapi-ts` instead of `openapi-fetch`. The
  thin-client option is the agreed direction. (If `openapi-fetch`
  turns out to be missing something we genuinely need during
  implementation, surface that and decide explicitly; do not
  silently swap.)
- Generating React Query hooks from the spec. TanStack Query
  usage stays exactly as today; only the function it calls
  changes.
- Adding ReDoc / Swagger UI to the SPA.

## Acceptance criteria

- [ ] `web/src/api/types/` does not exist.
- [ ] `web/src/api/schema.ts` (or the agreed location) is
      generated from `crates/backend-backendd/openapi.json` and
      committed.
- [ ] `web/src/api/client.ts` is ≤ ~80 lines and contains:
      a `createClient` call, a CSRF middleware, an error mapper,
      and the `ApiError` class. No hand-typed request/response
      shapes.
- [ ] `rg -n 'apiJson|apiFetch' web/src/` returns nothing (or
      only the new thin wrappers, if kept by name for ergonomics).
- [ ] Every FE call to the admin API goes through the
      `openapi-fetch` client.
- [ ] CSRF header is set on `POST` / `PUT` / `PATCH` / `DELETE`
      requests via the client middleware, not at the callsite.
- [ ] `rg -n 'ts(::|::export|#\\[ts\\()' crates/`
      returns nothing.
- [ ] `ts-rs` is removed from every `Cargo.toml` in the workspace.
- [ ] The `prebuild` (or equivalent) hook regenerates
      `schema.ts` from the committed `openapi.json`.
- [ ] `cargo test --workspace` passes.
- [ ] `cargo fmt -- --check` and
      `cargo clippy --all-targets --workspace -- -D warnings` pass.
- [ ] `cd web && npm test`, `cd web && npm run build`,
      `cd web && npm run test:e2e` all pass.
- [ ] `nix build .#checks.x86_64-linux.vm-test` passes (the spec
      artefact is produced by the backend derivation before the
      web derivation runs).
- [ ] `docs/backend.md` describes the new generation flow.
