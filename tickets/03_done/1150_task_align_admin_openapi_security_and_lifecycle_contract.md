# Align the admin OpenAPI security and lifecycle contract

Parent: none
Source review: `tickets/_review/codebase_2026-07-18.md`
Source findings: F-016
Source themes: C-004

## Outcome

The committed and generated admin OpenAPI document describes the security and lifecycle behavior the live admin router already enforces. Every protected state-changing operation requires the session cookie **and** CSRF header in one OpenAPI Security Requirement Object; no operation advertises the unreachable HTTP 423; store-backed operations advertise the existing HTTP 503 `store_locked`; and lock, rotate-key, and unlock document every currently emitted handler-domain status and canonical code.

This is contract correction only. Live middleware, routing, sessions, CSRF/origin enforcement, handler branches, response envelopes, status/code behavior, runtime mTLS API, and SPA behavior do not change.

## Security boundary

- Protected asset: accurate machine-readable propagation of the live admin session+CSRF policy and store lifecycle failure contract to clients, generators, scanners, and gateways.
- Actor/fault: an operator/tool consumes the generated backend contract; false OR security or unreachable/missing status branches can produce weaker gateway policy, incorrect clients, or failed automation even though live middleware remains protective.
- Boundary direction: live middleware/handler behavior -> utoipa source annotations -> generated OpenAPI -> generated clients/scanners/gateways.
- Invariant: one requirement object means session **and** CSRF for every protected mutation, and generated lifecycle statuses/codes equal existing handler behavior.
